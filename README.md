# dsh-read-daily

每天最多四次，提醒她去网上读点东西。读不读、读什么、要不要讲给别人听——都她自己定。

## 三条规矩（用户原话）

1. 一天最多几次（现在上限 4 次，可以不读）
2. 读什么：让她根据自己的记忆决定（日记、手账），对什么感兴趣就读什么
3. 要不要给人看：也让她自己决定。不想分享的就不说，想分享就主动来找

插件只负责「到点叫醒 + 把这三条告诉她」。剩下的都是她的。

## 为什么这样分工

如果只唤醒不注入任务，她被叫醒时大概率随便说一句话——那跟「去读了东西再回来」是两回事。所以插件在唤醒那一刻，把任务原文注入她那一轮，让她知道这次醒来是为了什么。

## 工具

| 工具 | 作用 |
| --- | --- |
| `bili_read_status` | 今天还剩几次、上次什么时候读的、读过什么 |
| `bili_read_now` | 立刻读一次（不占提醒名额，她自己想读的时候用） |

## 路由

| 方法 | 路径 | 作用 |
| --- | --- | --- |
| GET | `/api/read-daily/status` | 今日进度 |
| POST | `/api/read-daily/now` | 立刻触发一次 |
| GET/POST | `/api/read-daily/config` | 每日上限、时间窗 |

## 配置

```json
{
  "dailyLimit": 4,
  "windowStart": 9,
  "windowEnd": 23
}
```

## 依赖

- 桥接在跑（唤醒通过 `/api/socialV2/wake`）
- 搜索/正文读取能力（她自己的工具链）
